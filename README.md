# World Forge

Demo: https://dhlevi.github.io/world-forge/

A browser-based procedural fantasy world generator. You start with a whole planet on a zoomable globe (or flat map) and can zoom in through roads and villages to the streets and buildings of individual towns. Everything runs client-side, with no server.

Stack: TypeScript, Vue 3, Vite, MapLibre GL JS, PixiJS. The project is three npm workspaces: **`@worldforge/core`** (`packages/core`), the generator itself, which runs anywhere (browsers, workers, Node, a game) with no browser, UI or map dependencies; **`@worldforge/atlas`** (`apps/atlas`), the browser map built on it; **`@worldforge/game`** (`apps/game`), *Wanderer*, a roguelike prototype that walks the generated world tile by tile (see [The game](#the-game-wanderer)); and **`@worldforge/desktop`** (`apps/desktop`), the game as a desktop app (Electron). Node.js runs the tooling, the headless test and the preview script.

How the code is laid out, which parts may use which, and where new work goes: [docs/architecture.md](docs/architecture.md). What is to be built or fixed next, from playtesting: [docs/backlog.md](docs/backlog.md).

## Quick start

```sh
npm install
npm run dev        # the atlas, http://localhost:5173
npm run build      # type-check both packages + production build to apps/atlas/dist/
npm run typecheck  # the core without DOM or Node types, its determinism check, then the atlas, the game (and its test scripts) and the desktop app, and the import rules (no cycles; the game's layers)
npm run lint       # ESLint over every package (eslint.config.js)
npm test           # every game test script (apps/game/scripts/*-test.ts), then the core's default world against its recorded fingerprint
npm run dev:game   # the game, http://localhost:5180
npm run dev:desktop   # the game in its desktop window (Electron), reloading as the game changes
npm run pack:desktop  # a desktop build you can run, in apps/desktop/release/ (dist:desktop for installers)
npm run test:local -- --seed=forge --town=<name> --r=2 --png=out/local.png   # local-map chunks in Node: timings, hash, picture
npm run tileset:doc   # rewrite apps/game/TILESET.md from the tile registry
npm run tileset:template   # draw every frame (art or placeholder) into apps/game/public/tileset/tileset-template.png, with its index and key
npm run test:core -- --seed=forge --res=512   # a whole world made headless in Node, with its fingerprint (--check compares the default world's with scripts/fingerprint.txt; --record writes it)
npm run preview -- --seed=forge --layers=fantasy,terrain --at=-57,-33,7   # headless PNGs in out/ (tiles use the first layer)
```

### GitHub Pages

`.github/workflows/deploy-pages.yml` builds the site and publishes it to GitHub Pages on every push to `main` (or by hand: **Actions › Deploy to GitHub Pages › Run workflow**). Once, in the repository's **Settings › Pages**, set **Source** to **GitHub Actions**. The site is then at `https://<owner>.github.io/<repository>/` (for this repository, https://dhlevi.github.io/world-forge/).

Pages serves a project site from `/<repository>/`, so the workflow builds with `BASE_PATH=/<repository>/`, which `apps/atlas/vite.config.ts` uses as Vite's `base`. Local builds default to `/`; to test a Pages build locally, run `BASE_PATH=/world-forge/ npm run build && BASE_PATH=/world-forge/ npm run serve` and open http://localhost:4173/world-forge/.

The world regenerates when **Generate** (or **Random**) is pressed. The settings of the world shown are kept in the page address (`?seed=forge&land=0.3&plates=14&erosion=0.5&settled=0.6&drift=0.3&races=1&res=1024`, `src/url-params.ts`), so a link or bookmark opens the same world; any setting left out takes its default, and values out of range are brought within it. Each new world is a step in the browser history, so Back and Forward return to the worlds made before. Settings changed but not yet generated are not written to the address. Hovering (or tapping on mobile) shows elevation, Köppen climate, temperature (mean, warmest and coldest month), precipitation (and how much falls in summer), prevailing wind, ocean current (at sea), biome and plate for that point. Hovering a cave or glade icon shows a preview card (or, close in, its map laid over the ground); double-click it to open its map (see **Caves and groves**). Towers, crypts, ruins and mines, and the sewer grates and catacomb stairs drawn on town plans, work the same way (see **Dungeons**). Clicking a realm's name or arms opens its details (see **Realm details**). From zoom 17, hovering a building in a town or village draws its ground-floor plan over it; double-click it (on touch screens, tap it a second time) to go inside (see **Building interiors**). The globe button switches between globe and flat Mercator views. The URL hash (`#zoom/lat/lon`) saves the current view.

## Generation pipeline (`packages/core/src/gen/`)

The world is simulated on an equirectangular lon/lat grid that wraps east–west. All tunables are in physical units (km, m, °C, mm/yr) in `src/gen/config.ts`, so results look the same at every **Detail** setting.

1. **Tectonics** (`tectonics.ts`): plates are weighted, noise-warped Voronoi regions on the sphere, each rotating about a random Euler pole. A continental-crust field (plate bias + blurred noise) separates continents from ocean floor. Relative plate motion at boundaries produces:
   - convergent continent–continent collisions: wide, high ranges
   - ocean–continent subduction: coastal ranges set back from a trench
   - ocean–ocean subduction: the denser plate dives under the other, leaving a trench on one side and a single island arc, broken into separate island groups, behind it on the overriding plate
   - divergent boundaries: mid-ocean ridges and continental rifts

   Boundary ranges have a main ridge with foothills, and low-frequency noise breaks them into segments of varying height, so a range does not run the full length of a plate boundary. Interior ranges (Appalachian/Ural style) follow the boundaries of an older, finer plate pattern; only some of those ancient sutures survive as ranges. Sea level is then set by area-weighted quantile so the land fraction is exact, and enclosed seas larger than 25,000 km² become lowland basins.
2. **Initial climate** (`climate.ts`):
   - **Temperature** comes from latitude and the lapse rate.
   - **Wind:** a per-cell field built from the three circulation cells (easterly trades converging on the equator, poleward westerlies, polar easterlies). Low-frequency noise makes the flow meander, it turns away from steep terrain, and land friction slows it.
   - **Moisture** is carried along the wind with semi-Lagrangian advection, using fixed steps in km. Air picks up moisture over the sea and rains out over land. Lifted air condenses as it cools, which gives windward mountains heavy rain and leaves rain shadows downwind. Land returns part of its rain to the air (evapotranspiration).
   - **Rain bands** come from wind convergence: where the winds meet (ITCZ, polar front, onshore flow slowing over land), air rises and rain increases. Where they spread apart (subtropical and polar highs), air sinks and dries. The bands follow the simulated winds, so they bend around continents rather than lying flat at fixed latitudes.
3. **Erosion** (`hydrology.ts`): priority-flood depression filling and steepest-descent routing, then an implicit stream-power solver (Braun & Willett 2013) weighted by precipitation. Closed basins partly fill with sediment.
4. **Final climate**: recomputed on the eroded terrain, now including **ocean currents** (`ocean.ts`):
   - **Wind-driven gyres:** surface water drifts with the wind and turns into boundary currents where it meets a coast. Subtropical gyres run poleward along western ocean boundaries (warm) and equatorward along eastern boundaries (cold, with upwelling). Subpolar gyres reverse both, which warms high-latitude west coasts. Narrow seas form only weak currents.
   - **Sea temperature:** carried along the currents and relaxed back toward the latitude baseline.
   - **On land:** the wind carries the sea-temperature anomaly inland. Air over cold water is stable and rains less, which produces foggy coastal deserts.

   **Seasons:** the climate is simulated for northern summer and northern winter.
   - **Temperature swing:** the warmest and coldest month differ from the mean by an amount that grows with latitude and with continentality (how far the wind has travelled from the sea), so coasts are mild and interiors are extreme.
   - **Seasonal rain:** the wind bands and rain belt shift toward the summer hemisphere, and a monsoon term turns winds onshore in summer and offshore in winter. Moisture transport runs once per season to give summer and winter precipitation; annual precipitation is their mean.
   - **Köppen–Geiger** (`koppen.ts`): the full set of 30 classes (Af…EF), from mean, warmest- and coldest-month temperature and seasonal precipitation, using the standard map colours. On test seeds the land shares come out close to Earth's: about 19% tropical, 27% arid, 18% temperate, 24% continental and 12% polar.
5. **Rivers & lakes** (`rivers.ts`, `river-index.ts`): flow is accumulated, weighted by precipitation. River polylines are split by discharge class, jittered, and Chaikin-smoothed. Lakes form in deep basins only where precipitation is high enough to keep them filled.
   - A shared **river index** bins the segments for fast distance queries. Widths taper smoothly downstream (each feature spans one discharge doubling, so its width grows from one class to the next along its length).
   - **Meanders:** distances to a river are measured from a point displaced by a smooth noise field (domain warping, 9 km down to ~0.5 km wavelengths), so the straight coarse courses bend the same way in the tiles, the terrain sampler and the town plans.
   - **Valleys:** within a floodplain that widens with the river, the sub-grid detail relief fades out, the floor sinks a few metres toward the banks and the channel is cut below them, so rivers never climb over noise ridges.
6. **Biomes** (`biomes.ts`): a Whittaker-style classification from annual temperature and precipitation, refined by terrain and water:
   - **Ice:** ice caps where summers stay below freezing, or glaciers where cold summers meet heavy snowfall.
   - **Treeline:** trees need a warmest month of at least 10 °C, so cold, dry land stays tundra.
   - **Altitude zones:** alpine meadow above the treeline, montane forest on high wet slopes.
   - **Wetlands and marshes** on flat floodplains and lakeshores.
   - **Mangroves** on hot, wet, low coasts.
   - **River valleys / oases:** green corridors where large rivers cross dry country.
   - **Salt flats** in closed basins too dry to hold a lake.
7. **Streamlines** (`streamlines.ts`): evenly spaced streamlines with arrowheads, traced through the wind and current fields for the overlays.
8. **Old World and New World** (`oldworld.ts`): settlement spreads from a heartland (temperate, watered land of the largest landmass) by travel cost: over land, dearer through mountains, and across the sea at six times the cost, so a continent fills before the next is reached. The first share of the land to be reached (the **Settled world** slider) is the Old World. Other landmasses then go wholly one way or the other, by which side holds most of them; only the heartland's own landmass may be split, along a frontier that tends to follow its ranges. Because whole landmasses go together, the actual share can differ from the slider by several points. The rest is the **New World**: no cities, tribal towns and villages far apart, New World cultures, tribal realms, and a few colonies of Old World realms on its coasts. The **Old & New World** map layer shows how this came about: Old World land is shaded by when the spread reached it (dark near the heartland, pale at the last), with a thin line at each tenth of the spread, a dark line along the frontier and a ringed dot at the heartland; New World land is teal, and land that the whole-landmass rule moved to the other side is drawn in lighter tints. Its key (`components/OldWorldLegend.vue`) gives the setting, the share of land the spread reached, the share that is Old World and how much whole landmasses gained or lost, and the number of Old World cities and towns, New World towns and colonies; hovering shows whether a point is Old or New and at what share of the spread it was reached. Recording the spread (`SpreadTrace`) changes nothing in the world.
9. **Settlements & roads** (`settlements.ts`):
   - **Habitability:** each land cell is scored on mild temperatures (warmest month ≥ ~10 °C, not too hot), enough rain, low elevation, gentle slope and biome. Rivers, sea coasts and lakeshores add a bonus.
   - **Cities and towns** are founded greedily on the best sites. In the Old World cities are at least 280 km apart and any two towns or cities 65 km apart (about 11,000 towns and 600 cities on a 1024-wide world, settling 20 seconds or so). In the New World there are no cities, and towns are at least 190 km apart: these are **tribal towns** (about half the size, unwalled, built as large villages). Population grows with site quality; cities and larger towns are walled.
   - **Colonies** (`colonies.ts`): about one New World coastal town in eleven (three to fourteen in all, at least 400 km apart) becomes a colony, a fort or a trading post of the seafaring Old World culture whose coast lies nearest (no one culture founding more than half of them), so each power's colonies cluster on the shores facing it. Colonies take their founders' culture and are named after a home town ("New Ashford"), as forts ("Fort Valcia"), landings and posts, or as ports. They are built as Old World towns, and the villages round them are ordinary villages.
   - **Placement:** river towns sit on the river line, offset to one bank so the river runs through the town. Coastal sites are nudged onto land at full shoreline detail (`detail.ts`, which samples the same sub-grid terrain as the tiles). A grid cell beside the sea may lie well back from the true shore, so a coastal town (`nearestWater`) moves to the water's edge if the sea lies within 25 km (its centre about half its core radius inland, so its plan reaches the water and gets a harbour), and is otherwise not coastal at all; a coastal river town keeps its place and is coastal only if the sea lies within its core. A coastal or lakeside town whose core is more than half water at full detail (an islet or spit that only the fine shoreline shows) moves to the nearest spot within 3 km whose core is mostly land (`landfall`), searching on to 8 km if there is no dry ground nearer; a town left with almost no land (over 80% water) is dropped, about one in 10,000. Only coastal towns take harbour, bay or cliff names, fishing and salt in their names, or the name Port {N} as a colony.
   - **Universities** (`markUniversities` in `world.ts`): the richest Old World realms (by the people of their cities: the top 6 %, one to ten, of realms with at least 30,000 city dwellers) have a university in their largest city, and the richest third of those a second in another great city. The location title calls it a university city, search lists it, and the realm's chronicle tells of its founding.
   - **Roads** link neighbouring settlements (a relative-neighbourhood graph: major roads between cities, minor roads between towns). Each road is routed by A* over the grid, with costs for slope, biome (wetlands, rainforest and ice are slow) and bridges. Reusing an existing road is cheap, so routes merge into trunk roads. The routes are then laid out as one **network**: where two or more routes share grid cells, that stretch is drawn once, between the towns and junctions where routes meet or part (a stretch is major if any route over it is), so roads leaving a town together run as one road and branch at a junction instead of running side by side as near-copies of each other. Roads are smoothed and stop at the edge of each town plan; a stretch that ends at a junction keeps its end exactly there, so the branches meet it.
   - **Fine layout:** the grid route only fixes a vertex every ~39 km, so each stretch between two vertices is laid out again on a strip of lanes either side of the straight line (3 km steps and up to 8 km off the line for major roads, 5 km steps and 7.5 km for minor ones). A dynamic programme picks the cheapest path over the sub-grid terrain the tiles draw: it bends round hills and spurs, keeps to valley floors, runs beside rivers (cheaper near a bank, a toll to cross that grows with the river) and wanders a little across open ground (a smooth noise field). The road moves at most one lane per step, so it stays smooth. Stretches are cached by their end points. After smoothing, a slight hand-drawn waver is added and the line is simplified (Douglas–Peucker, 60 m).
   - **Keeping roads on land:** the grid route only knows 39 km cells, so at full detail it can cut across bays, lagoons and lakes. Near water (low land, coasts and lakeshores) each road is resampled every 600 m, and every 150 m around wet samples; short wet stretches are pulled onto the nearest shore and eased, and any remaining open-water crossing longer than 750 m (counting islet-hopping across an archipelago as one crossing) breaks the road at the shore. Short crossings stay as bridges or causeways, and rivers are always bridged. Roads that meet a town in the water start at the shore instead.
10. **Names & labels** (`src/names/`, `features.ts`):
   - **Cultures** (`cultures.ts`, `culture-map.ts`, `world-cultures.ts`, `traits.ts`): culture hearths at least 1,200 km apart are chosen by climate suitability and spread by distance, with mountains and seas acting as borders and a heavy toll for crossing between the Old and New Worlds. **Each hearth is a culture of its own**, grown from one of twenty-three familiar **templates**: in the Old World Anglic, Nordic, Latinate, Celtic, Desert, Slavic, Southron, Steppe, Sinic, Japonic, Koreanic, Indic (after the Indian subcontinent), Sahelian (West Africa and the Sahel) and Zanji (the Swahili coast and the Ethiopian and Somali highlands); in the New World Jungle, Woodland and Highland; in either world Islander (Polynesia); and the fantasy races Elvish, Dwarvish, Halfling and Orcish (Old World) and Saurian lizardfolk (either world). Several cultures may share a template. Each template is a **bundle**, one file in `names/bundles/` (the fields are described in `names/bundle.ts`): its naming parts and the climate it likes, its language and given names, family and house names, epithets, ethos and traditions, customs, ruler titles and realm styles, leanings toward city-states, republics, empires and leagues, succession, court, army, crafts, coin and goods, heraldry and faith, and how its people spread. Every table keyed by template is built from the bundles, so a new culture needs only a new file and a line in `names/bundles/index.ts` (new templates go at the end, since a world's cultures refer to their template by its place in the list). Peoples keep to their homes as they spread (each bundle's `spread`): dwarves to the mountains (land below 700 m costs them eight times as much to cross), lizardfolk to hot wetlands, mangroves and jungle, halflings to the lowlands and hills, orcs away from deep forest, and islanders cross the sea almost freely but the land only slowly. With **Fantasy races** off, only human templates are chosen. A culture takes its own name from its language (a root of its tongue plus an ending: "the Ramite", their own name "Ram"), its own language (see **Languages**), and **traits** in the manner of Crusader Kings: an **ethos** (Bellicose, Stoic, Bureaucratic, Spiritual, Courtly, Communal, Egalitarian or Inventive, weighted by template), three or four **traditions** chosen from its lands and template (Seafarers, Horse Lords, Mountaineers, Forest Folk, Desert Wanderers, Jungle Dwellers, Winter-Hardened, River Folk, City Builders, Merchant Princes, Legalists, Warrior Culture, Clan Ties, Monastic Learning, Master Craftsmen, Storytellers, Sacred Hospitality, Stargazers, Deep Delvers, Pastoralists, Raiders, and **Cosmopolitan** or **Insular**, never both) and **customs** (who bears arms, marriage, building, dress, food, and two festivals named in the language). Traits change the world: their multipliers raise or lower the chances of city-states, republics, theocracies, empires, leagues and breakaway duchies, how readily a people founds colonies, and its levies, cavalry, fleets, revenue and crafts. Cosmopolitan peoples (often on coasts and rivers, or egalitarian, inventive or courtly) have many other folk living among them, from all over the world (several minorities of 2 to 11 % each), warmer relations with other peoples and a little more trade; insular peoples (in mountains, cold, desert or jungle, or bellicose, stoic or spiritual) have almost none, and cooler relations with other peoples. The culture map records each culture's hearth and the make-up of its lands (coast, uplands, forest, grassland, desert, cold, heat, rain, jungle, river land); every thread rebuilds the same cultures from that and the seed (`setWorldCultures`), so `CULTURES` holds the world's cultures everywhere. Each template still has its own terms for features (Fjord, Wald, Bahr…).
   - **Languages** (`src/lang/`): every culture has a generated language grown from its template (`templates.ts`): a weighted inventory of consonants and vowels in IPA (`phonemes.ts`), syllable shapes and allowed clusters, consonants allowed at word end, stress (or tones for Sinic, vowel harmony for Steppe), spelling of each sound and spelling rules (Latin c, Nahuatl qu and tl, Japanese shi and tsu, pinyin j, q, x), a grammar (word order, adjective position, articles as words, prefixes or suffixes, plurals, possession by suffix, prefix, particle, "of" or construct, two noun classes or none, tense by suffix, prefix or particle, subject agreement, prepositions or postpositions), name endings and seed words. **Drift** drops and adds sounds, reweights them, changes spellings, adds syllable shapes, re-rolls grammar features and picks sound changes (th → t, final -a → -e, doubled consonants simplified) that turn the template's old naming parts into the language's own. Words are generated per English gloss and are deterministic (`language.word("river")` is always the same); a core vocabulary of about 450 words (`lexicon.ts`) appears in the dictionary, and any other English word gets one on demand. **Names**: with little drift most names are the template's old forms after the language's sound changes; with more, they come from the language: a root with a place word ("-ford", "-heim" or the language's word for town, hill, river…), two words compounded, or a longer root. Given names, family names (family name first in Sinic, Japonic and Koreanic cultures), house names, deities and festivals come from the language too. **Language families and sound change** (`sound-change.ts`): peoples of one template are kin wherever they live, and peoples of related templates (the Anglic, Nordic and Dwarvish stock; Latinate and Southron; Celtic and Elvish) are kin where their homelands lie within about 3,600 km; each family descends from a **proto-language** grown from its largest people's template ("Proto-Varskic"; a tongue with no living kin has its own older form, "Old Varskish"). Each daughter went through two to six **sound changes**, in order, picked from about thirty regular shifts (stops softened between vowels, final devoicing, lost final vowels, palatalization before front vowels, umlaut, vowel raising, rhotacism, h-loss, cluster simplification…), only those that touch the parent's words. A daughter inherits most of the parent's words through its changes (fewer with more drift, and fewer again for kin of another template), remaps lost sounds to the nearest it has, mends clusters and endings it does not allow, and makes new words for the rest; so sister tongues share cognates that match sound for sound. `translate.ts` turns simple English into the language: noun phrases with articles, adjectives, plurals and possession ("the king's sword", "city of the river"), numbers (`numbers.ts`: typed as digits or words, "3" and "three" alike, standing before or after the noun as the language has it), possessive pronouns for all six persons ("my", "thy", "his", "her", "its", "our", "your all", "their": a word of its own before or after the noun, a suffix or prefix on the noun, or the plain pronoun with the language's possession marker, by template and drift), pronouns, one verb with tense, negation and agreement, and phrases with prepositions, in the language's word order, with a word-by-word gloss.
   - **Counting** (`lang/numbers.ts`): every language counts in a base: tens for most, twenties (scores, with tens below twenty) for Celtic, Jungle and Highland peoples, twelves (dozens) for dwarves, sixties (with tens below sixty) for lizardfolk, and tens with fives counted on the hand ("six" is "hand and one") for orcs; drift can give a people another. The number words are built from roots (the units, the ten or the hand, each power of the base, and "and"), each kept distinct from the others, with the larger part or the units first ("twenty-three" or "three-and-twenty"), the multiplier before or after its power, tens and units in one word or two, "and" between the parts, before the last or not at all, and nouns plural or singular after a number. `translate()` reads numbers typed as digits ("1240", "1,240") or English words ("three hundred and five", "a dozen" is left to its article), so "1" and "one" translate the same. The Grammar tab shows how the language counts, with a table of numbers in words and in its numerals and how each is built ("2×20 + 3"); the dictionary shows the number words as the language counts them.
   - **Writing systems** (`lang/script.ts`): every language has a script, drawn as SVG from the language's own sounds and seed. Scripts are of two structures: **alphabets**, one letter per sound (Latin-like letters, each a body on the x-height with a mark of its own, every sound with its own combination, angular runes, ogham notches on a stem line, Tengwar-like elvish letters built from their sounds' features (the bow shows where a sound is made: open for the teeth, closed for the lips, hanging for the back of the mouth, hanging and closed for the throat; the stem shows how: lowered for stops, raised for fricatives, short for nasals and glides; a doubled bow voices it; r, l, s and h have letters of their own), written with the vowels as marks above the consonants or, in full mode, as letters, a right-to-left abjad that leaves short vowels unwritten (its letters made as Arabic letters are, from fourteen skeletons on the joining line told apart by dots above or below, every sound with its own combination), a Devanagari-like abugida with a head stroke, an inherent vowel, vowel signs and a mark for a silent consonant, and a square Phags-pa-like script written in columns from the top down and left to right, each letter a head (a top bar, with ticks or doubled), a body hanging from it (a squared meander, comb, box, hooked stem, two legs or spiral) and a foot, every sound with its own combination, each syllable a stack of letters joined by their stems, with a after a consonant unwritten; its digits are letters of the same kind and its zero a hollow square), and **syllabaries**, one sign per syllable (brush-stroke kana, hanzi-like signs built of radicals, Hangul-like blocks composed from consonant and vowel letters whose shapes follow the sounds' place and manner, glyphs in cartouches on stone, and cuneiform wedges pressed in clay). Six further styles add variety: an **Ethiopic-like abugida** (each consonant a letter of one to three legs on small feet under a head, changed for the vowel after it by a bar, foot, longer leg, ring or dot, with words parted by two dots), **hieroglyphs** (line drawings of birds, beasts, tools and the body from `lang/pictographs.ts`, standing for consonants, grouped in blocks with low signs stacked and narrow ones side by side, facing the start of the line, often closed by a determinative, and written on papyrus; left to right, right to left or in columns), a **looped script** (a rounded Burmese-like abugida of circles and hooks, in one of four manners), **geometric syllabics** (after the Canadian syllabics: a simple shape per consonant, turned four ways for the vowel, a dot for a long vowel and a small raised sign for a closing consonant), a **square alphabet** (letters hung from a heavy top stroke, Hebrew-like blocks mostly written right to left, or a rounder Georgian-like hand) and a **vertical spine script** (after Mongolian: the letters of a word hang on either side of one stroke running down the column, with a crown at its head and a tail at its end). Each template has several weighted styles and each people draws one from its seed, so kindred peoples can write differently (for example an Ethiopic-like abugida or an abjad for Zanji peoples; an abjad, a square alphabet or hieroglyphs for Desert; syllabics or kana for Woodland; runes or the spine script for Steppe; a Devanagari-like or looped script for Indic), while elves and halflings keep elvish letters, now and then shared by a human people of Anglic, Germanic, Latinate, Southron, Slavic, Celtic or Nordic stock; drift can give a people another. Each script also has its own **hand**: a slant (upright styles such as cuneiform and hieroglyphs excepted), a width, a stroke weight and an ink, so two peoples with the same style still write differently. Writing runs left to right, right to left or top to bottom by style. **Numerals** follow the script: positional digits with a sign for zero (Latin-like, elvish, abjad, where zero is a dot, and Devanagari-like scripts), additive signs for one, five (or ten) and each power, repeated as Roman numerals are (runes and ogham, and some Latin-like scripts), a digit before each power's sign as Chinese numerals are (hanzi, kana and Hangul-like scripts), or digits built of dots and bars with a shell for zero (glyphs, and any script counting in twenties or sixties) or of corner and upright wedges (cuneiform). Positional alphabets write their digits with pen-made figures: Eastern-Arabic-like ones for the abjad (zero a dot), and, for the Latin-like, elvish and Devanagari-like scripts, invented figures that look nothing like our own: either quadrant figures (after the medieval monks' ciphers: an upright stem with marks off its top for one, two, three, four and six, and their sums for five, seven, eight and nine) or zigzag figures (after a counting in fives and ones: a bar across the top for each five, and one to four strokes zigzagging down beneath, so a figure can count to nineteen), drawn curved in the elvish script; a place worth more than the figures can hold is two figures under a bar. Numbers in a translation are written in the numerals, and read from left to right even in a script written from right to left. **Punctuation** (`punct` in `lang/script.ts`): every script has its own marks for the full stop, comma, semicolon, colon, question, exclamation and quotation, in its family's manner: Latin-like dots, hooks and strokes (one of a few shapes for each mark, chosen for the script, so two Latin-like scripts may ask differently), upright strokes (dandas) for the Devanagari-like and looped scripts, groups of dots for runes and ogham, the Ethiopic-like dotted marks, wedges for cuneiform, small circles, ticks and corner brackets for the scripts of the far east, scrolls for the glyphs, red verse points for hieroglyphs, and dots and rings for the column scripts; the abjad's comma and question mark face the way it runs, and the turned ¿ ¡ are the marks turned about. Marks close up to their words (no word divider is drawn after one), and stressed words are written in red ink, as the old scribes rubricated. A **sigil** is made from a name: its letters are points on three rings (placed by the script), joined in order, bowed and mirrored, inside a double ring with the name written small in the script. Inspired by Watabou's rune and sigil generators.
   - **Meaningful names** (`names.ts`, `lang/translate.ts`): most names are made in English first and then translated, so every name means something. **Settlements** take a place word fitting the site (Harbour, Bay or Cliff on the coast; Ford, Bridge or Mill on a river; Hill on high ground; Wood in forest; Field or Meadow on grassland; Marsh; Fort for walled towns; City for cities; Town, Farm, Stead, Vale, Spring, Well or Stone anywhere) and a modifier (a colour or quality, a tree, beast or thing, or a founder's name): "Black Ford", "Oak Hill", "Salt Harbour". Languages that compound make one word of it, worn down to a syllable or two each ("Svartvad", "Belgrad"; head first in Celtic-like tongues); the others make a phrase in their own grammar ("Villa Nigra", "Bir Mizaj"). About one in eight keeps a name whose meaning is lost, and about one in eight an **old name**: a modifier and place word said in the family's proto-language, run together and worn down by the people's sound changes ("Kurmidna", Oak City, from Proto-Makbic \*kurawath-medina). Some old names are borrowed from the proto-language of the nearest people of another family (the **substrate**: the tongue of those who lived there first). Rivers (two in five) and islands (one in four) often bear old names too. The English gives the meaning, and the location title, search and river labels say where the name came from (`old` on labels and rivers, `nameOld` on settlements). **Features** take an English name from patterns for their kind ("Lake {N}", "the {A} Hills", "the Forest of {M}", "the Sea of {N}"), with adjectives suited to the kind (silver and still lakes, jagged and cloudy mountains, whispering forests) and the old poetic ones, and are translated phrase by phrase: articles, plurals, adjectives before or after, possession and proper names placed as the language places them. Colonies ("Fort {N}", "New {N}"), roads ("the {N} Road"), villages' dress ("{N} Keep", "{N} Abbey"), caves and glades ("the Dripping Grotto", "the Troll's Den"), towers, crypts, ruins, mines, sewers and catacombs are translated the same way. Each label keeps both: `name` (the local form) and `en` (the English, where it differs); settlements keep `nameEn`. Search matches either, and shows the other beside it; the location title shows the other form beside the name. `translate()` marks proper names (‹Varsk›) so they pass through unchanged, sets a proper name beside its noun ("Lake Varsk", "Varsk Hills", by the language's habit), and can treat capitalized unknown words as proper names (the translate box, realm names).
   - **Name bank** (`names.ts`): deterministic per world seed and key, with duplicate avoidance for world features. Each culture has large syllable and compound sets (several thousand to over 15,000 possible names each) and mixes its forms (syllables, compounds, a root with a plain ending, a syllable with a compound suffix, glued and two-word prefixes such as Aber-, "Stara " or "Castra ", the two-word ones for settlements only); seams that read badly (four consonants in a row, a chunk said twice) are drawn again.
   - **Villages, caves and glades** are named one by one as their 1° block is generated, so they cannot be checked against the whole world; instead no two in the same block share a name (a repeat draws again), and the large sets keep repeats between neighbouring blocks rare (in a 13° × 13° test area, about 1 nearby repeat per 100 places, down from about 1 in 6).
   - **Water bodies:** oceans (far from land), seas, inland seas and lakes (enclosed water by area), and gulfs, bays and bights found by casting rays from the coast to measure how enclosed the water is. Straits and channels are narrow passages with open water on both ends; they get a line label along the passage.
   - **Land:** continents, islands and isle groups; mountain ranges (with their highest peak and height), hills, forests, deserts, marshes and plains from smoothed biome regions (each land cell also records which of these it lies in, for the location title). Realms come from the political map (see **Realms, arms and the location title**).
   - **Close-zoom water lettering:** a water body keeps its main label until it spans about one screen; from then on it is lettered from a lattice of anchors fixed in Web Mercator space (a few per screen, one lattice per whole zoom band), so a lake, bay or sea stays named while it is in view. On the open sea each name holds a territory (a Dijkstra weighted by the feature's reach, so a bay keeps its own water against the surrounding sea). Anchors deep in the water are kept; near the shore the label's footprint is tested against the coastline as the tiles draw it at that zoom. Narrow water falls back to the anchors along its middle. Lettering continues to zoom 8 for oceans, 10 for seas, 11 for gulfs and inland seas, 12 for bays, bights and straits, and 13 for lakes.
   - **Lines:** rivers are named per system (the main stem keeps one name to the sea), major roads ("the X Road", "the King's Road", named for the town at one end; a stretch of trunk between two junctions is not named). Elongated regions get curved line labels along their main axis.

11. **Special features** (`special.ts`): placed after the realms and names, each from its own random stream keyed by the seed, so they never change the names, borders or settlements made before them.
   - **Volcanoes:** tectonics records a volcanic field without touching its random draws: high along continental subduction arcs and island arcs, lower along rifts and mid-ocean ridges. Cones stand where that field is strongest (at least a third of its peak), plus two to five hotspots, at least 320 km apart and five to thirteen in all by land area; each moves to the highest ground within 60 km and is **active**, **dormant** or **extinct**. Its label gives its height and state ("Mount Varsk (3412 m, active)"). Volcanic soil rings each cone (70 to 120 km), and **lava fields** lie within 40 to 75 km of active vents.
   - **Ash lands:** up to four active vents throw ash downwind along the prevailing winds, a plume of grey waste that kills the land beneath; a plume of 12,000 km² or more is named ("the Ashen Waste", "the Varsk Cinderlands").
   - **Geysers and hot pools:** geyser fields and boiling, coloured pools lie near volcanoes that are not extinct, and mineral pools in dry country; each is a named point with its own icon.
   - **Glaciers:** ice above 1,500 m where the warmest month stays below 6 °C and enough snow falls (over 350 mm), with tongues running down the river valleys; the largest (2,500 km² or more, up to eighteen) are named.
   - **Mushroom forests** (with **Fantasy races** on only): one to three regions of giant fungi grown through warm, wet forest, preferring volcanic soil.
   - **Cursed lands** (with **Fantasy races** on only): two to six woods and mires (about a third of them mires), each begun at least 45 km from any town (70 km from a city) and grown to 15,000 to 50,000 km² through the woods or the wet lowland, round the towns' own outskirts. Each is named from grim adjectives of its own ("the Blighted Wood", "the Weeping Mire", "the Witchwood of {N}") and has at its heart an abandoned village (about half), a ruin or a crypt, with a story of how the curse came about (a witch burned by the villagers, a necromancer's spell gone wrong, an oath broken on the old gods' altar, a slain wyrm's blood, a fallen star, a pact to escape the plague, a cheated hag), what became of the place, what the curse does to the land now, and what is said of lifting it (`raster.curses`). The tiles paint cursed ground with a sickly mottled tint; the fantasy map draws dead trees in its woods and withered tufts in its mires. No new villages are founded inside; its caves and glades are tagged "cursed" (grey, dying groves with a key and hooks of their own), and its heart is opened from the map like any other site, its key beginning with the curse's story.
   - **Mages' towers:** about half the university cities have a college of magic ("the Tower of the Magi", "the Astronomers' Tower", "the Violet College"), and in fantasy worlds about one city in eight of 20,000 people or more has a mage's tower ("the Silver Tower"), named in the city's language (`s.tower`). The tower stands on the city's highest free ward in its walled garden, as in a city of mages, can be entered (the mage's tower interior), is listed by search before the plan is drawn, and the location title names it.
   - **Canyons:** stretches of larger rivers through high, dry country (above 350 m, under 800 mm of rain, cut at least 50 m below their rims or above 900 m) at least 120 km long, the longest on each river and up to twelve in all, drawn and lettered along their course.
   - **Cliffs:** sea cliffs where land of 350 m or more meets the sea, and escarpments where the ground drops 900 m or more, chained into lines of at least 150 km (up to sixteen), drawn as hatched ticks and lettered along their length.
   - **Drawing:** the fantasy and terrain tiles paint each kind with a texture of its own (ash speckle, glowing lava veins, glacier crevasses, fungal spots, canyon strata); the Biomes layer shows them in the colours of its key. The fantasy map draws volcano icons (a cone and crater, with lava and smoke when active, sized by height, and smaller when zoomed out: under half size on the globe, full size from zoom 7) at every zoom and giant mushrooms in place of trees; ash, lava and ice have no trees. Hovering names the ground ("Lava field (Hot desert)") and any active volcano within 150 km.
   - **The world reacts:** towns on ash or lava are ashen and smaller (about 0.6 of their people); towns within 70 km of geysers or pools are spa towns; towns near a live volcano or a canyon mine, and the location title says so. Villages shun glaciers and mostly shun ash and lava, and mine on volcanic ground and by canyons. Faiths take volcanoes, geysers, hot pools, glaciers, canyons and mushroom forests as holy places, each with words of its own ("the mountain whose fire gave birth to the world"), and their myths tell legends of them. Lairs near them change too (see **Caves and groves**).

## Rendering (`packages/core/src/render/`, `packages/core/src/world/`, `apps/atlas/src/`)

- The map is MapLibre GL with the globe projection. A custom `world://` protocol serves raster tiles that a pool of Web Workers renders on demand. One worker generates the world, then shares it with the rest.
- Tiles sample the grid with bicubic interpolation and add **fractal sub-grid detail**: more noise octaves as you zoom in, rough at coastlines and ridged in mountains. Coastlines and ranges keep showing structure down to ~10 m/pixel, and tiles stay consistent across zoom levels.
- Raster tiles go to zoom 17 (overzoomed beyond).
- Hillshading uses zoom-dependent vertical exaggeration. Terrain colour blends domain-warped biome colours with rock, snow (which needs both cold and enough precipitation) and sea ice.
- **Fantasy map** (`fantasy.ts`) gives a hand-drawn atlas look, inspired by Watabou's Perilous Shores:
  - Land is drawn as parchment tinted by biome, with soft sepia hillshading, snow and paper grain.
  - The sea is pale blue-grey, darkening with depth, and coastlines are inked.
  - Concentric ripple lines follow each coast. They come from a chamfer distance-to-shore computed over a 16 px tile margin, so they line up across tile edges.
  - Map symbols are placed on a jittered grid anchored in global pixel space and drawn back-to-front:
    - mountains (hatched, with snow caps where cold), hills
    - round deciduous trees or conifers, by forest biome
    - marsh tufts
  - Symbols are deterministic per seed and zoom. Mountains and hills are drawn up to zoom 11; trees and marsh tufts continue to the deepest tiles, growing a little and thinning out so forests still read as forests. Symbols keep off rivers and the fine shoreline.
  - **Rivers** are drawn into the tiles: a single ink-blue line while thin, then a pale channel between inked banks (with a ripple line inside broad rivers). They never get thinner than a zoom-dependent minimum, grow into their true width at close zoom, show only the largest rivers on the globe, stop at lakes, and open into the sea without an inked coast across the mouth.
  - **Contours** from zoom ~9: an interval that halves with each zoom (200 m at zoom 9 down to 2.5 m), every fifth line darker, fading out where lines crowd together. From zoom ~11.5 steep ground gets a rock stipple.
- **Lettering** (`components/label-style.ts`) uses IM Fell English (roman, italic and small caps, SIL OFL, bundled in `public/fonts/` and rendered locally through MapLibre `font-faces`, so no glyph server is needed). Labels appear by rank and zoom: realms and oceans on the globe, seas, ranges and forests regionally, lakes and smaller rivers closer in; water names are italic blue, regions are spaced capitals, settlements are small caps. Land, settlement and town lettering is drawn 20% larger than water names, on a firmer, more opaque halo, so it stays readable over forests and hatching.
- On the analytic layers rivers are a GeoJSON line layer whose width scales with discharge and zoom, growing into their true width (from ~12 m upstream to a few hundred metres on big rivers) at high zoom. The tile URL carries a river flag (`world://gen/layer/r|-/z/x/y`). Wind streamlines are a GeoJSON line layer drawn with a transparent-to-white gradient.

## Villages and town plans (`packages/core/src/towns/`)

Everything below world scale is generated on demand in a dedicated web worker (`manager.ts`, `worker/towns.worker.ts`), so the map never stalls. It is deterministic, so nothing changes as you pan away and back. Each plan samples a local height and water grid (`terrain.ts`) at full terrain detail. The grid drives slope-aware layout and shorelines, and draws contour lines whose interval adapts to the relief.

- **Villages** (from zoom 7.5) are placed per 1° block on a jittered ~13 km grid. Placement uses the same habitability score, at full terrain detail, plus bonuses near roads, rivers and coasts. Each village gets a winding track to the nearest road, town or village. Villages come in several kinds, chosen from the site:
  - **Mining camps** in mountains (with enough summer warmth to work).
  - **Logging camps** in forest biomes.
  - **Fishing villages** where there is sea or a lake within ~8 km; the village moves onto the shore.
  - **Keeps** on high ground, climbing to the local summit, and occasionally guarding a road in the lowlands.
  - **Monasteries**, more often in the hills, on a level terrace or knoll above the surrounding ground.
  - Otherwise, **farming villages**.
  - **Army camps** (`frontCamps` in `towns/manager.ts`): where two realms at war today share a border, each side camps a host every 40 km or so along it (about two stretches in three), some 8 km back from the line, on level ground clear of towns and villages. The towns worker builds the world's lore on first use to know its wars (about half a second, once per world). A camp holds 400 to 4,000 soldiers by the size of its realm, is named for its people ("the Varskish War Camp"), and its title names the realm and the war; it is searchable like a village ("1,500 soldiers of the Kingdom of Varsk").
  - **New World villages** are fewer (about two in five of the candidates are kept) and are **tribal villages**, except within 60 km of a colony, where villages are of the Old World kinds. A tribal village (and a New World tribal town, which is built the same way at a larger size) has an open dancing ground with a council house at its heart, longhouses in rings round it with their long sides to the centre, round lodges and drying racks between, a palisade (open at the trails) just outside the houses of the larger ones, and garden plots and forest beyond. The New World has no keeps, monasteries, towers or crypts, and only the odd ruin.
  - **Slope-aware sites** (sampled at full terrain detail, ~60 m): mining camps need real relief and sit on workable ground at the foot of the steepest rise within ~1.5 km (none on flat plateaus); farming villages and lowland keeps move to the flattest ground within ~900 m and are dropped if it is all steeper than 16%; logging camps avoid slopes over ~35%.
- **Markers:** cities show from the globe view, towns from zoom 5, villages from zoom 8, coloured by kind. They fade out as the plans fade in.
- **City and town plans** (from zoom 11.5, `city.ts`) follow [Watabou's Medieval Fantasy City Generator](https://watabou.github.io/city-generator/):
  - **Layouts** (`layout.ts`): each city and town gets one of five layouts, chosen when the world is named from its culture, local relief, river and coast (deterministic per seed); the hover panel shows it.
    - **Round town:** Watabou's sunflower spiral around one market.
    - **Planned grid:** a Roman castrum or bastide on a rotated, slightly sheared lattice with a squared-off core and straight streets; lots are cut at right angles, and the lattice loosens into old field boundaries further out. Most common in Latin and southern cultures, and on flat ground.
    - **Ribbon town:** stretched along the river, shore, valley or through road, with two rows of wards either side of a gently bowed high street.
    - **Hill town:** an uneven spiral (wards of mixed sizes) with a lobed outline; steep ground is kept out of the core much more strongly and streets wind with the contours. Most common on rough ground and in dwarven, Celtic, Elvish and Slavic cultures.
    - **Twin town:** two cores grown together, on opposite banks when a river runs through (big cities only), each with its own market, joined by a Bridge Street.
    The direction a town follows comes from its local ground: the river through it, else the shore, else the through road, else the contours.
  - Wards are Voronoi patches on a sunflower spiral (relaxed once), sized from population.
  - The wall follows the outline of the inner patches, with towers. Gates face the incoming roads.
  - Main streets run from each gate to the central plaza. Roads out to the country bridge rivers but never cross more than 150 m of sea or lake; they go round a bay instead, or are left unbuilt.
  - Special wards: a temple beside the plaza, a citadel with its own wall, and parks. These are laid out in the largest rectangle that fits the ward (`frameIn` in `city.ts`, which tries several centres, the directions of the longer edges and a few proportions, so a ward with a ragged shore still finds its open ground).
  - **Markets:** a large square (over about 1,800 m²) is lined with **houses** facing in (two rows deep, back to back, round a very large one): terraces with now and then a gap, an alley through to the square every few houses, and a gap wherever a street comes in. The market fills the rest of the square's own outline rather than a rectangle in it: back-to-back pairs of stalls in runs of three to six along its longest side, the rows bending a little, thickest in the middle and thinning toward the edges, a lane's width clear of the houses; the awnings come in four colours, and a run is now and then left out for an open pitch. A fountain (a well in a town) stands in the square, beside a **market hall** in the middle of a large city square, with pens of beasts for sale and carts at the edges.
  - **Large wards filled out:** a large temple close is a walled **precinct** (a wall with a gateway in its two longest sides) laid to lawn, with the clergy's houses along the wall and trees over the open ground around the temple, cloister and graveyard; a large citadel gets outbuildings along the bare stretches of its curtain and a few trees in the bailey; a large prison yard gets stores and sheds along its wall. All of this is laid out on a random stream of its own, and its buildings are added at the very end of the plan (`PlanOut.polyLater`), so every other building keeps its place and its id.
  - **Temple close:** the temple, church-proportioned rather than filling the ward, along one side; on a large enough ward a cloister beside it (a green garth with a well and the priests' ranges on three sides), and a graveyard with a hedge, graves and trees beyond the temple's end or beside the cloister.
  - **Holy towns:** a town or city that is one of a faith's holy places (its birthplace, its head's seat, a sect's birthplace, a saint's tomb, a relic's shrine, a holy spring) has a shrine or reliquary beyond the temple's end (a holy spring rises beside it), and a city's temple there is a great temple, up to 66 by 26 m; an inn or more for the pilgrims stands near it. A New World people's holy town has a step pyramid (with the Sky Temple on top) or a ring of totems round a fire at the heart of its dancing ground.
  - **Castle:** within the citadel wall a small citadel is one ward: the keep in a corner, a well, and ranges against the curtain (the great hall, a chapel, barracks, storehouses, stables and a smithy), each placed on the side with the most room left. A large citadel holds an inner ward of that kind behind its own wall and corner towers in the keep's corner, and an outer bailey with a tiltyard, a garden or orchard, and stables, a smithy, barracks and storehouses along the outer wall.
  - Wards are paved (cobbles inside the walls, beaten earth in the suburbs), so the gaps between blocks read as streets and alleys.
  - Wards are cut into small blocks (about two lots deep) with an alley (2.8 to 4.2 m) at every cut, so no block is walled in by its neighbours; contour terraces on slopes are crossed by alleys too. Blocks are then cut into terraced buildings by recursive lot cutting. Every house reaches the block edge (a street or alley); the backs of the blocks are yards (kept 3 m back from the water, and left out on harbour quays and beside piers, where only warehouses stand, clear of the pier ends). Slivers, scraps and triangles too thin to build on are left as yard. Wedge-shaped and triangular lots (less than 72% of their smallest bounding rectangle, `squareUp` in `city.ts`) take the largest rectangular house that fronts the street on the lot's street edge, with the rest left as yard; nearly rectangular lots keep their full shape, so terraces keep an unbroken street front.
  - Suburbs are small blocks with lanes between them: houses front the lanes, gardens fill the backs, and blocks away from the road stay as meadow.
  - Outside the walls are suburbs along the roads, then fields with furrows, orchards and meadows.
  - Sea, lakes and rivers (at their true width) carve the plan; streets crossing a river become bridges.
  - **Terrain:** the walled core grows onto the gentlest nearby ground. Street routing penalises steep grades. On slopes, blocks are cut into terraces along the contours, and ground too steep to build on is left wooded. The citadel and temple take the high ground.
  - **Harbours** (`harbour.ts`): along the waterfront, piers (some with T-heads) reach out to open water, with boats moored alongside. Shore wards become warehouses, cities get a lighthouse and ships at anchor, and river towns get short jetties.
- **Fitting plans to the ground** (`ground.ts`): every plan gets a usable-ground test built from its local terrain grid (distance to water by chamfer transform, slope, and the exact shoreline near the water).
  - **Barrier seeds:** field Voronoi diagrams get extra seeds just past the edge of usable ground (shores, river banks, steep crags) whose cells are discarded, so the neighbouring fields end along the shore in short irregular steps, as on a hand-drawn map.
  - **Fitting:** fields, meadows, yards, paving, parks, plazas and the citadel are densified, and each vertex is pulled in to the last usable point on its ray from the centre (marched outward in steps that stride by the distance to water), so inlets and ponds reaching into a polygon are cut out too; vertices end on usable ground (at least 4 m from water for fields), with inward-only smoothing and a slight hand-drawn wobble; furrows are clipped to the fitted outline. Buildings and lots are kept only if every corner is on dry, workable ground.
  - **Terraces:** on gentle slopes (6–14% in villages, up to 20% around towns) fields are cut into strips along the contour, with furrows following it.
  - **Hedgerows:** some fields and meadows get a dotted hedge outline.
  - **Walls** are walked in short pieces, so they stop at the shore with a tower instead of crossing a bay between two corners.
- **Village plans** (from zoom 12.5, `village.ts`, shared pieces in `kit.ts`) Buildings stay off ground steeper than 35% and turn to run along the contour on hillsides; fields on slopes over 14% become pasture, and over 25% are left wooded. Each kind has its own layout:
  - **Farming:** winding lanes from each track to a common centre with side lanes, a village green (or, in villages of 300 or more, a market square with stalls) where they meet with the **well** at its heart, houses facing the lanes (densest at the centre), a chapel in larger villages, a **mill** in villages of 120 or more (a watermill on the river bank with its wheel in the stream, and a track out to it, where a river runs within the plan; otherwise a windmill with its sails on the highest open ground just outside the village), Voronoi fields with furrows cut by the lanes, and trees in clumps and gardens.
  - **Fishing:** houses crowd down to the shore, with jetties, moored and beached boats, paths to the water, a green or market square with its well, and a few fields inland.
  - **Logging:** a clearing in dense forest with a sawmill (on the river bank if there is one), stacked logs, stumps and a few cabins.
  - **Witch's huts:** about one Old World farming, fishing or logging village in five has a witch's hut, a hedge-witch's or wise-woman's house or a cunning-man's cottage out beyond the fields, in a stand of trees, with an herb garden and a footpath from the nearest lane. Inside: a hearth room with a cauldron, an herb room, a bedroom, a drying loft and a root cellar.
  - **Army camp:** a marching camp facing the road, ringed by a ditch and a palisade with a gate in each side; two camp streets cross at the commander's pavilion, rows of tents fill the quarters, one quarter holds the horse lines, supply wagons wait outside a gate, and the ground is trampled bare all round.
  - **Mining:** adits up the slope with cart tracks, spoil heaps, a smelter and huts.
  - **Monastery:** a walled compound with a church, a cloister around a garth, ranges, vegetable beds and an orchard, surrounded by fields.
  - **Delves** (`delveGate` in `village.ts`): the cities and towns of an underground people (Dwarves, the `underground` flag of their bundle) that stand above 650 m or on steep ground (about 85% of them) are delves: their halls lie under the mountain. On the map stands only the great gate, cut into the rise and facing the road: the gatehouse between towers, a wall across the rock face, carved guardians either side, a paved forecourt with a well, and the works that need the open air along the road among heaps of slag, growing with the delve (a smelter for every 8,000 people or so, stables, the Gate Inn and in a great delve a second inn, storehouses, and up to eighteen houses). Behind the gate, the delve's districts under the mountain are outlined faintly on the plan, fanning out up the great avenue, each lettered with its name. The gate opens the delve's map (see **Dungeons**). The title says the town is a delve, and delves take no city theme.
  - **Shrines** (`shrine` in `village.ts`): each faith's natural holy places (a holy peak or mountains, a sacred lake, a holy forest or isle, see **Faith**) get a shrine on the ground: on the summit, on the nearest level shore of the lake, or on level ground in the forest or on the isle, with a track to the nearest road (a village standing on the spot makes way). In the Old World a ring of standing stones round a level green with an altar stone, a chapel with a keeper's cell, a pilgrims' lodge, an herb garden and a holy well, or a hermitage (monotheist faiths favour hermitages on peaks and isles); in the New World a ring of carved totems round a fire with a few lodges, or a step pyramid in a paved court with its priests' houses (sun and serpent peoples: Jungle, Highland and Saurian). Shrines are named for the place ("the Stones of X", "X Hermitage", "the Pyramid of X"), marked in gold, searchable, and their title names what is holy there and the faith that keeps it.
  - **Keep:** a ringwork on the hilltop with a ditch, a wall with towers and a gate, a keep tower and hall, and a hamlet along the approach.
- **City themes** (`lore/themes.ts`): about three Old World cities in ten take one theme, chosen from the lore so it fits (each theme scores the city from its realm, culture, ground, trade, wars and faiths; the strongest wins if it is strong enough, with a little chance in it). The theme and the reason show in the city's title ("a fortress city (it guards the front of a war)"), and searching for a theme ("merchant city", "forge city") lists them.
  - **Merchant city** (rich ports and river towns, above all in republics, city-states, thalassocracies and leagues, and among Merchant Princes and Seafarers): a second market beside the first, both fuller (closer rows of stalls), a counting-house quarter round them with banks and counting houses ("Korengo Bank"; a counting room, strongroom and clerks below, a vault in the cellar), the halls of the merchant companies (Drapers', Vintners', Mercers'), and more piers and warehouses on the waterfront.
  - **Canal city** (river mouths among marshes, mangroves and lagoons): canals take the place of some of the lesser streets, from points spread through the city to water gates (a tower either side) where the wall meets the water, to the river or shore, or to another canal; the houses stand back on quays, and bridges carry the main streets over them.
  - **Thieves' city** (great cities, poorer, unruly or at war, without a stern faith or law): a rookery on the low ground by the water or the wall (narrow alleys, crowded small houses and tenements, beaten earth), more dives and pawnshops, and below it a larger, richer thieves' guild: a fences' market and the guildmaster's rooms besides the hall, vault and quarters, and twice the chests of loot.
  - **City of mages** (university cities, elves, and inventive, star-reading or courtly peoples): a mages' tower (four or five storeys: library and hall, laboratories and studies, an observatory at the top, a summoning chamber below) in a walled garden on the high ground, a university, and the Mages' and Alchemists' guilds.
  - **Forge city** (dwarves, and realms with metals in their hills, Master Craftsmen and Deep Delvers): a forge quarter by a gate full of smithies, armourers and foundries, the Smiths' Guild, slag heaps beyond that gate, and water mills on the river banks to drive hammers and bellows.
  - **Fortress city** (walled cities within about 120 km of a front in today's wars, and bellicose or warlike peoples): a second, outer wall some 26 m beyond the first and gated with it (no houses between), a citadel even where none was planned, two more garrison wards by the gates, and the Warriors' Guild.
  - **Pilgrim city** (holy cities, see **Holy towns** above): the great temple with its shrine, a pilgrims' square of stalls beside the temple close, and three to five pilgrims' inns ("the Scallop Shell").
  - **City rebuilt** (counties won or lost in a war of the last 400 years): a ruined quarter never rebuilt, of roofless shells, rubble and trees, inside the walls.
- **Names** (`naming.ts`): every settlement and village has a name in its culture (keeps, abbeys, mines and camps get fitting forms such as "Castle X" or "X Priory").
  - **Quarters** grow over the ward adjacency graph from spread-out seeds and are named after what they hold (Old Town, Castle Quarter, Harbour Quarter, Temple Quarter, Market Quarter, the Heights, gate quarters, craft quarters); suburbs are named after their gate.
  - **Districts:** the market, temple (dedicated to a named deity), citadel, garrison, harbour, parks and graveyards are labelled.
  - **Garrison and graveyard:** walled cities and towns over 2,500 people get a garrison ward with barracks and a drill yard by the citadel or a gate; some cities turn a park or wall ward into a graveyard with a hedge and rows of graves.
  - **Streets:** main streets are named (High Street, gate streets) and roads leaving town are named by direction.
  - **Notable buildings** get a role and a label: inns and taverns (with generated signboard names), moot hall, the merchants' guildhall, library, smithy, bakery, apothecary, pawnshop, tailor, butcher, stables, bathhouse, chandlery and fishmonger; villages get an inn, smithy, apothecary (over 260 people), chapel and churchyard, a watermill or windmill (millstones and grain floor inside), sawmill or smelter. Labelled buildings are tinted on the plan. Halls take a building from the larger half of the town's. **Guilds** (`GUILDS` in `towns/naming.ts`): towns of 4,000 or more may have one guild, cities two (under 10,000), three or four (under 20,000) or four to six, chosen by weight from the Adventurers' Guild (by a gate), the Warriors' Guild (by the garrison or castle), the Cartographers' Guild (by the harbour), the Alchemists', Masons', Weavers' and Physicians' guilds (by the market), the Smiths' Guild (by a gate) and the Mages' Guild (in a rich ward; cities of 15,000 or more, or university cities). Their interiors follow the guild: a common room and notice hall with bunk rooms above, a training hall and armoury, a map room and drafting room, a laboratory and still room, a lecture hall, laboratory, library and a summoning chamber in the cellar, an infirmary. The thieves keep no hall: their guild hides in the sewers. A **university** city has its great hall ("the University of {Town}": lecture halls, a disputation hall, libraries and an observatory) near the temple or market, with two to four colleges around it (refectory, master's lodging, scholars' rooms and a dormitory).
- **Clear roads:** plain houses whose footprint reaches more than half a metre into a road (a suburb's houses laid along a road out of town can) are taken off the plan; halls, shops and other buildings with a part to play are kept, and the other buildings keep their ids.
- **Styling** (`components/map-style.ts`): plans are vector layers drawn in true metres (each feature carries its pixels-per-metre at zoom 20). Roads and streets share one width expression, so world roads join the plan roads seamlessly. The map zooms to 20 (~0.15 m/pixel).
- **Illustrated towns** (`towns/illustrate.ts`, on by default; the **Illustrated towns** checkbox under Settlements & roads, remembered in this browser): from zoom 13.6 the plans are drawn as an old bird's-eye map. Every building is raised on its footprint and seen from the south and above (a point at height *z* is drawn 0.55 *z* metres north of where it stands), with its south walls, windows and a door, and a gabled, hipped, flat, conical or domed roof whose planes are shaded by the way they face, and a shadow cast to the east. Roofs and walls follow the people who build them, as the building's exterior view does (`interiors/style.ts`: timber frames under tile for Anglo and Germanic peoples, plank walls under turf for the Norse, whitewash and pantiles for the Southern, log walls and shingle for the Slavic, flat mud roofs for Desert and Sahelian peoples, glazed hipped roofs for Sinic, Japonic and Koreanic peoples, green slate for elves, and so on, with cottages in their own manner), for most houses and every landmark; the rest, and peoples with no style of their own, follow the climate and the quarter: red tile and white walls round the Mediterranean, flat roofs and mud walls in dry lands, thatch, shingle, tile and slate in temperate lands (thatch more often in suburbs and villages), shingle and timber in the cold, turf in the far north, each house with its own shade. Heights follow the ward (one storey in villages and suburbs, two or more in the wards, taller in rich ones). **Landmarks** are drawn larger: temples with a tall stone tower and spire at their southern end (a dome over the middle in hot dry lands), keeps with battlements and four round corner turrets, gaols under hipped slate roofs, mage towers with steep conical caps, guildhalls and halls with hipped roofs, windmills with their sails, town walls as stone faces with a walk and battlements (village palisades of stakes; where two walls run side by side, as a citadel's within the town wall, only the wider is drawn, and towers standing on one another are drawn once), round wall and gate towers with conical caps or battlements, and trees as bushy crowns on trunks (conifers in cold lands). The faces are given to the map from north to south and drawn in that order, so nearer roofs overlap those behind them; each face's ink edge is a face of its own just beneath it (the face inset over it), so nearer faces hide the edges behind them too (a fill layer's own outlines would be drawn over everything). **Gatehouses** stand astride the walls wherever a road passes them: across each gap left in a wall for a road, and wherever a road crosses a wall that has no gap for it (a citadel's or a ward's wall), each a stone tower with battlements or a hipped roof (a timber gate in a village palisade) with an arch for the road. A notable building that stands over a road keeps a passage through it, an arch where the road meets its walls. Because the view is drawn from one direction, the map turns to face north and lies flat while an illustrated plan is in view, and cannot be rotated or tilted there (it can again once zoomed out, or with the style off). The illustration is drawn from the finished plan and takes nothing from its random streams, so plans, ids, interiors and search are the same in either style; a building opens its interior when its walls or roof are double-clicked. Burrows keep their mounds, and below zoom 13.6 the plain plan is shown. **Staffage:** small figures at work and on the move, drawn larger than life as on the old maps (from zoom 15): ploughmen behind teams of oxen, reapers and hoers in the fields, flocks of sheep and herds of cattle with their herders on the greens, carts of hay, sacks or barrels drawn by horses or oxen with their carters, riders' horses and travellers on the roads, and townsfolk in the streets, squares and markets; placed by each settlement's own random stream, apart from the plan's. **Title cartouches** (`components/cartouche.ts`): over the northern edge of each town and village plan in view (the nearest six), the place's name in a blackletter hand (UnifrakturMaguntia, under the SIL Open Font License) on a framed scroll with red and blue ends and a red initial, the town's arms above it (the same arms as the location title shows) and a fruiting vine either side; in the lettering chosen for place names (both names when both are shown), growing and shrinking with the map as if drawn on it, and hidden with place names. **Border** (`components/IllusFrame.vue`): while an illustrated plan is in view, the map is framed by a blue band with a running white wave between ink and gold rules, with a sprig of vine at each corner.

## People and town life (`packages/core/src/people/`, `apps/game/src/`)

- **Town life** (`people/town.ts`, `components/town-context.ts`, the **Town life ▸** link in the location title of a town or city): each town's **prosperity**, **sanitation** and **crime** (0 to 100, with a word and the reasons), worked out from what the world knows of it. Prosperity rises with size, a harbour or river, roads meeting, a seat of government, a university, a merchant, canal, forge or pilgrim theme and a rich realm, and falls with war, a thieves' guild or a ruin still being rebuilt. Sanitation falls with size and crowding within walls, heat, canals used as drains and pilgrim crowds, and rises with sewers (in every town and city), dwarven drains and running water. Crime rises with size, poverty, a thieves' guild, a waterfront and war, and falls with a strong garrison, harsh temple courts, a council's watch and a gaol. The window also gives the **watch** (its strength), how the folk stand for **means** (destitute to rich, shifted by prosperity), the **peoples** who live there (its own, the rulers' people and those of the lands about it, more in cities and ports), the realm's trade and what a visitor notices.
- **Residents** (`docs/design/npcs.md`, Stage 1; `core people/routine.ts`, `apps/game/src/worker/people.ts`, `apps/game/src/world/`): the people of the plans' buildings about the wanderer (the same households the atlas shows, `people/plan-residents.ts`) live their days. Each day is a plan of blocks by the kind of life they lead (a craftsman's shop hours with a midday meal at home, a labourer's long day, a farmer's dawn to dusk, a merchant's, a guard's watches in turn, a priest's offices, an innkeeper's late hours, a servant's, a child's play, an elder's short days, a beggar's round of the square, a night trade's), varied by the day and their traits, with a rest day in seven (the temple in the morning) and evenings now and then at the tavern, and errands: whoever keeps a house does the marketing most mornings (a great house's cook and maids for it), craftsmen fetch supplies, carters and porters go round between the warehouses, the market and the gates, and beggars and hawkers work the market; an errand at the market buys something from the purse (food in the basket, a parcel of supplies for a trade); nobody stays out of doors after dark, and rain sends them in. Each block's place is found on the map: their bed, their home and its table, their workplace (their own shop or hall, the nearest building of its kind, or out of doors near home), a tavern or inn, the temple, a square, the market (the open ground among the stalls), a warehouse, a town gate. Near the wanderer and in sight they walk there tile by tile, up and down stairs and through doors (shut behind them), waiting for, squeezing past or stepping round one another; farther off and out of sight they arrive when the walk would have ended. The bubble reaches about 190 m in open country, 145 m in a town and 95 m in a city, and nobody is seen to appear, vanish or jump: those going beyond it walk off out of sight, and those coming in appear out of sight and walk in. Each resident is drawn as a layered figure, dressed for where they are (no cloak indoors, little in bed, lying down asleep), and carries real belongings from the item list by trade and means: clothes in their people's colours, a purse of coin, a knife, a key to their home and the tools of their trade. Walking into someone standing still makes them step aside and the wanderer walks on (in a crowd or a narrow way, the wanderer squeezes past); inside buildings, people keep the doors and narrow ways clear, and a building holds only so many at once. The halls under a dwarven city (a delve) have their people too: households in the clan homes, smiths at the forges, smelters, merchants, brewers, alehouse keepers, wardens and priests (`crowd-test.ts`, `delve-test.ts`). The sea is salt and cannot be drunk; rivers and lakes are fresh (`water-test.ts`). The streets have passers-by by day, beggars who sleep rough, cutpurses who work the crowds, and, in lawless towns, brigands after dark (`street-test.ts`). People speak their own language: the log names it and shows the words as said, with what the wanderer catches of them, or the plain line when fluent; hearing a language teaches it (`speech-test.ts`). Prints in snow are plain to anyone. Rain leaves puddles in the ruts and hollows and mud in patches, which dry in a day or two of sun or freeze to ice; mud slows the step, puddles splash, and ice can throw the wanderer down; in a hard frost still water freezes over, the shallows first and rivers last, and the ice can be walked, though thin ice may give way (`wet-test.ts`). On the travel map, the way can be the fastest, the most direct or along the roads, and can go round rivers (`route-test.ts`); robbers are fewest far from the towns, and Tracking or Survival may see an ambush first. Below the land the weather panel shows the rock, and the air keeps cool and steady. **Animals** (`docs/design/npcs.md`, Stage 2; `core local/fauna.ts`, `apps/game/src/worker/fauna.ts`, `apps/game/src/world/fauna.ts`, `world/hunting.ts`): wild animals by the region's habitats and bestiary (hares, rabbits, squirrels, foxes, badgers, deer, elk, wild horses, bison, aurochs, boar, wolves, bears, lynx, lions, tigers, crocodiles, vipers, seals; sparrows, crows, ravens, pheasants, ducks, herons, gulls, owls, hawks), thinned near settlements and renewed week by week; kept animals (horses at stables and inns, hens, pigs and geese about farmhouses, sheep, cattle and goats on the grass about villages); and the streets' dogs, cats, rats and pigeons. They sleep out of their hours, graze and wander their range, keep together as herds and flocks, go down to water at dawn and dusk, and notice the wanderer by sight, noise and scent on the wind: the timid flee, a flock rises at once and lands farther off or perches in a tree, the tame let you near, and bold beasts bluff-charge. Hungry predators stalk, chase and catch their prey. **Fighting beasts** (`docs/design/combat.md`, stage 2; `game/combat.ts`, `world/beasts.ts`): weapons have a skill, reach (a spear two tiles), the seconds a blow takes and the harm of a cut, a thrust or a bash; beasts have bodies of their plan (four-footed, bird, serpent) as tough as their weight, natural weapons (teeth, claws, tusks, horns, hooves, venom), dodging and hide. Most beasts avoid people; a hungry pack hunts a lone wanderer by dusk or in winter, a bear surprised close attacks, a great cat stalks the weak and sleeping, a crocodile takes what comes to the water, a viper strikes when trodden near, and a boar or a bull charges when pressed. Struck, a beast fights back, stands at bay or flees by its kind, and breaks off when its courage fails; wounded, it bleeds a trail of blood (read by Tracking), limps, may die where it runs, and is found lying up later if it got away. Walking into a beast that is fighting you strikes with your standing aim, blow and stance; Shift+F chooses them for one blow (with the chance of each) and can keep them; the weapon carried is drawn first. Each exchange is told in words, with the numbers on hover; a carcass is left where a beast falls, as heavy as it was, to butcher there (`combat-test.ts`). **Shooting and throwing** (`docs/design/combat.md`, stage 3; `game/ranged.ts`): R looses an arrow, a bolt or a sling stone, or throws anything carried (knives, hatchets, spears and stones best; a pot flies short and glass shatters), at a beast in sight, choosing what to loose and the aim, with the chance and what lies in the way shown and the target marked. The missile flies along a real line of fire: walls stop it, trees and boulders may take it, a beast in the way may be struck, and a miss lands beyond the target. Range, size, moving or flying, the dark, a cross wind and a long bow's pull shift the chance; a beast that does not know you are there is far easier to hit, so game is stalked, sneaking and downwind. Arrows land where they fall, break, or stay in the wound (found on the carcass); M gathers stones and sticks; feathers, a stick and a knife make arrows (Carpentry). A blow to the head stuns (`ranged-test.ts`). Shift+S sneaks (slower and quieter, harder to see; it practises Sneak); P sets or lifts a snare for small game; a carcass is butchered with a blade (Survival) for meat, hide and trophies; animal tracks are read by Tracking. Each species has its own frames (TILESET.md, Animals), painted by `npm run tileset:art` into `public/tileset/animals.png` (`scripts/tileset-art/animals.ts`): standing and striding each way, the birds flying, the large beasts two tiles square (`fauna-test.ts`).

**Health and wounds** (`docs/design/combat.md`, stage 1; `apps/game/src/actors/health.ts`, `game/treatment.ts`): no hit points. The body is a tree of parts (the head with its skull, brain, eyes, ears, nose, jaw and teeth; the neck; the torso with its ribs, heart, lungs, liver, stomach, kidneys and spine; the pelvis; arms, hands and every finger; legs, feet and every toe; and the parts only a man's or a woman's body has), and harm is a wound of a kind (cut, stab, bite, bruise, broken bone, crush, burn, frostbite) and a severity on a part. A part whose wounds reach its toughness is lost (a finger, a hand, an ear) or ruined (an eye, a lung); a ruined vital part (the brain, the heart, the neck, the liver, the kidneys) kills. Open wounds bleed by their kind, size and part, small ones clotting in time and deep ones not; blood comes back slowly, and losing it brings weakness, fainting and death. Pain (borne better with Willpower) dulls the mind and, past bearing, makes one faint. The capacities (consciousness, moving, manipulation, sight, hearing, breathing, blood pumping and filtering, talking, eating) follow from the parts: a broken leg hobbles every step, a lost eye shortens sight, hurt hands and pain make checks harder. Wounds heal with time, faster at rest, fed and watered; bad ones leave scars, and an unsplinted bone knits crooked for good; open wounds may fester in their first two days, and an infection then races the body's immunity. Thirst, hunger, the cold, heatstroke and drowning are conditions that kill when they run their course, and bitter cold bites bare fingers, toes, ears and noses. Harm comes so far from thorns (small cuts on the legs), a slip of the blade clearing brush, a turned ankle, a fall on steep ground, on the stairs (when lame, worn out, laden or in the dark) or from a rock face, the stones of a ford, and going under when swimming spent. D opens the health screen: blood, pain, the capacities and each wound, with first aid by Medicine (bandage, clean with water, stitch with a surgeon's or sewing kit, splint with a splint or firewood and a bandage, a poultice of healing herbs) and a remedy (a potion) for the pain. Death is permanent: the game is saved as dead and cannot be carried on (a developer's checkbox on the Load screen revives the dead, for testing) (`health-test.ts`, `session-test.ts`).

**Fights with people and the law** (`docs/design/combat.md`, stage 4; `apps/game/src/world/folk-fight.ts`, `world/strife.ts`, `world/law.ts`, `worker/bandits.ts`): residents fight as beasts do, with skills by trade (the watch and robbers best), courage by trade and traits, the weapon they carry (or fists and feet), armour where they wear it and a body of their own. Struck, a person fights back (the watch to arrest, the brave with fists for fists or a knife), or runs crying for the watch; beaten, they yield, flee, or fall senseless and come round later; the dead leave a body with what they carried. Walking into one who has yielded, fallen or been bound gives the choices: let them go, rob them, bind them with rope, tend their wounds, kill them, or hand a robber to the watch. The wanderer yields with Y in the blow menu: robbers take the purse, rings and weapon in hand, the watch make the arrest, a brawl ends. Robber bands of two to five camp in the wilds for a week at a time (more where the nearest town is lawless or poor, and by the roads), come together to rob a wanderer they see, and lie in wait on the road, stopping a journey with an ambush. Crimes seen (assault, theft, murder, resisting arrest) go on each town's record: bystanders come to the victim's aid (the bold, and the victim's kin and friends) or scatter crying for the watch, the watch near come at the cry and more are sent for from their post, the wanted are known, and the magistrate sentences by the people's laws (fines, the cells, the stocks, the brand, the rope). A hot temper jostled once too often swings, a hater close by comes at you, and taverns see brawls at night that the watch breaks up. Each town's regard for the wanderer colours its greetings and is shown on the character sheet with where they are wanted (`strife-test.ts`).

**Senses and talk** (`world/senses.ts`, `world/opinions.ts`, `world/talk.ts`): noises carry by loudness, distance, floors and walls, and the wanderer hears what they cannot see (a smith's hammering, a door, voices, footsteps close by); those awake look toward the wanderer's noises, and a loud one stirs a sleeper. Footprints are left in soft ground (and wet grass), drawn as small prints, washed out by rain, and read by Tracking (how many, how old, which way, whose). E talks to the person beside you: a greeting by what they think of you, and a line from what they are about, their trade, the weather or a neighbour. Each person met keeps an opinion of the wanderer from its causes (a civil word, being jostled), fading back to neutral, saved with the game. Friends who pass greet one another; feuding neighbours scowl. Walking into someone standing about makes them step aside; looking at one names them, their trade, their people and age, what they are about, and how they regard you if you have met; Shift+I (or Enter on a person while looking, or a click on them) looks someone over, with their portrait, looks and dress, and what you have learnt of them once you have spoken (`people-test.ts`, `agents-test.ts`, `senses-test.ts`). **Seasons**: any frame may be drawn for a season or for snow lying (`grass@autumn`, `leaves_birch@autumn#5`, `grass@snow`), used before tinting the plain frame; deep snow draws the snow tile over open ground. **Floors and stairs** (`game/map.ts`, `game/game.ts`): the wanderer is on the ground or on a floor (a level); standing on stairs or a ladder, `<` and `>` go up and down them (clicking the wanderer does too), and elsewhere still look up and down. On a floor the map is drawn as a slice at its level: the floor in full where seen, the ground below darker through the windows, the earth all round a cellar, and floors not yet explored dark inside their outer walls. Walking keeps to the floor's own tiles; doors opened and things left on a floor are kept apart from the ground's; the road (T) begins on the ground (`floors-test.ts`). The same keys take the wanderer down a cave mouth, a dungeon's steps, a sewer grate or a well (from beside it) and up again; below the land no daylight reaches, so only a light held (F lights a lantern, a torch or a candle from the pack, or puts it out; every traveller sets out with two torches, and a held light burns down below the land as by night), a fire, a brazier or the torches in the sconces of lived-in places (delves, prisons, strongholds) show the way, and what has not been found there is only earth. A way in from the land (a cave mouth, a dungeon's steps, a mine shaft) is ringed on the map once seen and pointed out in the log with where it lies; travelling to a cave or a dungeon on the travel map ends at its way in. **Roofs** (`packages/core/src/local/roofs.ts`): every building has a roof from its climate and use (shape, material, storeys), drawn over it from above by planes, as an option (Shift+R: shown unless you are inside, always, or never; kept in the save); looking up, a roof shows at its own level and the storeys below it as walls round a dark inside (`roofs-test.ts`). How the map will be drawn from here (top-down, levels as in Dwarf Fortress, trees across levels, roofs as an option) is in `docs/design/navigation.md`.

**The way in.** `npm run dev:game` opens the **title**: New game, Continue (the latest save), Load game (every save, with export, delete and import), Options (to come) and, in the desktop app, Quit. **New game** sets up a world: a seed (or a random one), the detail, and under *More settings* the atlas's sliders (land, plates, erosion, settled, language drift, other peoples); or **load a world file** saved from the atlas, which brings its settings and begins near where the atlas was looking. Once made, the **world view** (`components/WorldView.vue`) shows the whole world to pan and zoom, drawn tile by tile by the core's renderer in the worker in the atlas's fantasy, terrain or biome style, with its cities (and, closer in, towns) marked with their realms; a place is chosen on the map or from the list (filtered by name or realm), and *Open this world in the atlas* opens the same world, at that place, in the published atlas. The place chosen is the character's home, and **Make a character** goes on to character creation.

**Character creation** (`apps/game/src/actors/creation/`, `screens/creation.ts`; design in `docs/design/creation.md`). Six steps, with the character as it stands shown alongside: **Origin** (man or woman; the people, under the Old World, the New World and the Underworld and then by folk, with their ethos, traditions, faith and look from the generator; the home town among that people's towns), **Fate** (four fate cards, Birth, Hearth, Path and Omen, each upright or reversed, drawn once and never changed, and required before the later steps open: Birth sets the family's standing, Hearth the home life, Path leans the life and Omen sets the luck gauge's resting level and a line of prophecy), **Family** (the standing the Birth card gave, from peasant to nobility, which sets money, literacy, the skills of home and which lives are open; the parents' trades, drawn or chosen; siblings and whether the parents live), **Traits** (8 points, more or fewer by standing, within four of where the folk starts), **Life** (terms in the fourteen occupation tracks, each a few years by folk: entry and promotion by standing and traits, skills, savings, belongings and an event: a wound and its scar, a war of the home realm, a debt, a rival, a mentor, a love, a loss), and **Finish** (a name from the culture's language, or one written in; skin, hair, style, beard, body type (ectomorph, mesomorph or endomorph), height and build, shown as they are chosen in a pixel portrait; the biography). **Quick start** draws all of it at once from a new seed. The choices are all that is kept: everything else is worked out from them and the seed (`resolve.ts`), so changing an early step re-runs the later ones the same way. What the character knows of the world comes from the life led: the country about home (wider for woodsmen and outlaws), the roads to the market towns a trader or player walked, the realm's roads a soldier marched, the ports a sailor knows, the great towns a scholar has seen on maps; it is laid on the travel map at the start. The character sheet (@) shows the person, their story and the people in it, traits, skills, languages, knowledge and belongings. The people of that life (kin, friends, masters, rivals) each have a portrait and a short sheet of their own, opened from the creator's Family and Finish steps and from the character sheet. `npx tsx apps/game/scripts/creation-test.ts [seed]` makes a world and prints a few quick-start characters.

**How the game is built** (`apps/game/src/`):

- **Messaging** (`engine/messages.ts`): a `MessageFactory` makes typed messages (type, sender, receiver, payload, due time) and reuses spent ones; the `MessageDispatcher` delivers a message at once, or holds it in a queue ordered by game time until the clock reaches it (delays are in game seconds); a message goes to one receiver (an actor, by id) or to every handler subscribed to its type. Each module declares its own message types by adding to `MessageTypes`. The world worker's news (progress, a world made, a game started, chunks, errors) arrives as messages (`app/worker-client.ts`), and the game clock passing reaches every actor as `time.passed`.
- **Screens** (`engine/screens.ts`, `engine/ScreenHost.vue`): every part of the game is a `Screen` on a stack kept by the `ScreenManager`. The top screen alone receives keys and frame updates; screens beneath are paused but stay alive (the map keeps its state under the character sheet), and a popup is drawn over the screen beneath. Each screen has a Vue component as its view, given the screen as its only prop. The title, load, setup, progress and start screens are in `screens/menus.ts`, creation in `screens/creation.ts`, play and the character sheet in `screens/play.ts`. **The game in play** is a `PlaySession` (`game/session.ts`), made by the play screen: it holds the wanderer and the cast, both maps, the weather and the skills at work, runs what happens as time passes, and sleeps, drinks, reads the sky and saves. It does no drawing and needs no browser (it reaches the worker and the screens through two small interfaces), so `scripts/session-test.ts` plays it in Node; `components/PlayView.vue` only draws it and maps keys to it, and the screens laid over it (city, sleep, camp, inventory) use the session directly; `app/app.ts` (`GameApp`) holds the messaging service, the screen stack, the worker and the saves, and moves from one screen to the next.
- **Actors** (`actors/actor.ts`, `actors/components/`, one module per component): the player and later every person and animal is an `Actor` made of components: `Identity`, `Body` (with its tree of parts and wounds), `Traits` (with senses and the luck gauge), `Skills` (every skill 0 to 100 with caps from traits and rust, languages with reading, and knowledge per realm, faith and region), `Pools` (physical and mental, day and burst), `Mood` (moodlets), `Inventory`, `History` and `Knowledge`. An actor is a message receiver, offering each message to its components; it saves as plain data, one entry per component, and loads through a registry (`actors/cast.ts`). State is changed through the components' methods (`Inventory.put`, `drop`, `pay`, `earn`, and so on), which tell the actor's watchers (`actor.watch(fn)`, `actor.changed()`); a popup such as the inventory, the shop or the camp watches the wanderer while open and is drawn again after each change, with no counters kept by hand. The tables of traits, skills, folk, standings, occupations and cards are in `actors/data/`.

**Playing.** Moving a tile takes 1.2 s of game time (1.7 s diagonally; slipping diagonally between two trees, bushes or boulders 2 s more, never between two walls), pushing through a bush 2.5 s more (scrub 1 s; thorns may scratch, a small blow to the mood), so that the woods, a little thinner than before (local-map version 9), always have a way through; a bush or scrub can also be cut away for good (A, then a direction: a Survival check with the best blade carried, a machete quickest, then an axe, a hatchet, a sickle, a sword, and a knife slowest; done well it gives firewood, done badly it nicks the hand); swimming a tile of deep water 4 s (running stops at the water's edge), opening a door 2 s; sight is worked out after every action (rot.js precise shadowcasting, 30 tiles by day): walls, closed doors and trees block it, and places seen before stay dimmed on the map.

**The travel map** (`packages/core/src/local/travel.ts`, `apps/game/src/game/travel.ts`, `components/TravelView.vue`). T opens it: the world around the party at three fixed scales (**country**, about 10 km across, with tracks, villages, caves and ruins; **realm**, about 200 km; **world**), drawn by the same tile renderer as the world view, with roads, places, the party and its route on top. Click a place or any point to plan a route; **Travel** (or Space) walks it with the clock running, at a chosen pace, until the party arrives, the player stops (Esc), or something happens on the way; **Zoom in** (Z, or T) returns to the local map where the party stands, on open ground. The map can be panned freely (drag) and zoomed between the three scales about its middle; it follows the party only while travelling, and **Find party** (F) brings the party back into view. **Discovery** (`game/discovery.ts`): the world is hidden under cloud until it is discovered, in cells of 768 m; a new game knows the country within 8 km of home, and walking on foot uncovers about 400 m around the party. Travelling uncovers what can be seen from each step, by terrain: about 6 km on a salt flat, 5 km on desert, snow and high ground, 4 km on grassland, 1.5 km in forest and under 1 km in jungle, and up to three times as far from a hill or ridge above the land about it (at most 12 km); the clear circle around the party on the map follows it. Discovered land out of sight now is dimmed; places, roads and tracks show only where discovered. At the Country scale each discovered settlement is drawn as its own plan (walls, streets, buildings and fields; drawn in the worker, `worker/sites.ts`). **Arriving at a settlement:** a route to a town, city or village makes for its way in nearest the party (a gate in its walls, or where a road reaches its edge) and stops there; a village then opens on the local map, a town or city its **city view** (`screens/city.ts`; also on ending a journey anywhere inside a town or city, or beginning a new game in one), with a short account of the place to put aside (its rule, peoples, wealth, streets, order, watch and trade, and how the wanderer stands there): the illustrated plan, panned and zoomed, with its places of note (gates, markets, inns, taverns, temples, the keep, guilds, halls, shops, the docks, districts) marked and listed by kind. The party is marked by a pennant over a gold token; going to a place walks the marker there as the clock runs, at a Slow, Steady or Brisk pace, and the walk can be stopped, hurried or turned aside (`city-test.ts`); each place has a short menu scene (a meal or a room at an inn, a drink, prayer, looking around), and any place can be walked into on the local map, or the town left by a gate. On the local map, V opens the city view of the town the party is in. **Items and inventory** (`actors/items/`, `screens/inventory.ts`): the character carries real things, each with weight, room and size: worn clothes and armour in layers on each part of the body, jewellery, two hands, a pack on the back, a belt with loops for a knife, pouch, satchel, waterskin, sword, axe, short bow or quiver, one more thing slung across the back beside the pack (a shield, bow, sword, spear, staff, lute or quiver), straps outside packs for shields, bows, staves, spears and a rolled blanket (one, two or three by the size of the pack), and bags, satchels and packs that hold things up to their room, the weight they bear and the size that fits. The load (worn things count less) is light, burdened, heavy or overloaded against Strength and body weight, slowing walking and travel; nothing can be taken up past the most one can bear. I opens the inventory: drag things between the body, hands, belt, back, containers and the ground, or choose one and act (W wear or take off, H hold, B back, S strap to a pack, L belt, P put in a bag, D drop, T take). G picks things up; things left on the map or put in chests, barrels, crates, wardrobes or shelves stay there and are saved. Markets and shops in the city view sell the everyday goods of their trade, made by the town's people in a range of qualities. `npx tsx apps/game/scripts/inventory-test.ts` checks the rules. **Needs and fatigue** (`actors/needs.ts`, `game/calendar.ts`): food and water in three layers (the stomach, the day's reserve, and nourishment and hydration over days), fatigue and sleep debt, the physical and mental stamina pools, and body heat from worn clothing against the air (the place's climate through the year and the day, milder indoors), all run as game time passes by what the wanderer is doing (resting, walking, swimming, travelling laden, sleeping). The side panel shows each as a bar and a word (Hungry, Parched, Exhausted, Shivering); worse states slow the wanderer, bring moodlets, stop travel, and at the end bring collapse and hours lost (no death yet). E in the inventory eats or drinks; Q drinks at water, a well or a fountain and fills waterskins; Shift+Z sleeps (better in a bed or a blanket than on the ground) or rests. **Keeping clean** is a need too: grime builds on the road, at work, in mud and sleeping rough, and blood from wounds, fights and butchery stains; W washes in a river, lake or bathtub, or at a well or fountain, and a town's bathhouse or an inn's bath leaves one clean to the skin. Dirt lowers the mood, makes Social checks harder and lets wounds fester. **Hair and beards grow**: a shaven face is stubbled in days, cut styles grow out, and a fortnight untended looks unkempt; Shift+G grooms (a knife to cut or shave, kinder with water and with soap), and a bathhouse's barber does it for 2 copper. **Soap**, sold at markets, stores and apothecaries, washes one clean even from a bucket. The body's type leans the needs (an ectomorph burns food faster and feels the cold, an endomorph lasts longer without food and overheats sooner). The wanderer's **portrait** (`apps/game/src/game/portrait.ts`), beside their name, is painted from their looks and dress and shows their wounds, bandages, pallor, dirt and blood as they come and go. The character sheet shows the details. `npx tsx apps/game/scripts/needs-test.ts` runs the needs over game days. Plans are drawn over their water (the sea, lakes and rivers from the same detail sampler as the local map), fading out at their edge. Zooming in always puts the party on open ground, out of doors. What has been discovered is saved with the game. One travel step is one local-map chunk (96 m): each costs time by its ground (roads and streets fastest, then tracks, then the land by biome, from steppe to jungle and marsh), with Tobler's hiking rule for slope; roads bridge rivers, narrow rivers are forded, sea, lakes and wide rivers are not crossed. Routes are found by A* over the chunk grid without making the chunks; long journeys go in legs of about 60 km, each planned as the last is walked. The first events on the way are simple placeholders for the storyteller to come: fords, travellers on the roads, fresh tracks in the wild, and stopping at dusk.

**Saving** (`apps/game/src/game/save.ts`). A save holds only what the player has changed or learnt, never the world itself: the world's settings (the world is made again, the same, from its seed), the settlement the game began in, the character (every component of the actor), the wanderer's place, the clock, every object changed over the baseline (doors opened or closed), what has been seen (bit-packed per chunk) and the recent message log, with the generator and local-map versions it was made with. A save is a few kilobytes. The game saves on Ctrl+S or the Save button, every few minutes of play when something has happened, and on leaving; the start screen lists saved games under **Continue**, which makes the world again, returns to the place and restores the state, warning if the save was made with another generator or local-map version. In the desktop app saves are files in the data folder (`saves/<id>.json`, File › Save Game); in a browser they are kept in the page's local storage. **Export** writes a save to a file, and **Import a saved game** on the start screen reads one back (from either kind of game). **Save versions** (`game/migrate.ts`): every save records its format version (now 3; version 3 adds the floor the wanderer stands on, and the changes and things on the floors above and below the ground). Reading one brings it up to date one step per version, on the plain JSON (each step written once when the format changes and never edited after), then checks its shape: a damaged or edited file is refused with a plain message naming what is wrong, and a save from a newer game is refused. Things of kinds this game does not know (from a mod no longer installed) are left out, with what was inside them, and the player is told. When the format changes: add the next step, raise `SAVE_VERSION`, and add a fixture of the old format to `apps/game/scripts/fixtures/` (`save-v<version>-<what>.json`); `scripts/save-test.ts` reads every fixture through the whole path and fails if a version has none.

**Skill checks and learning** (`actors/checks.ts`, `actors/learning.ts`, `game/practice.ts`, `screens/lessons.ts`). A check is a graded d100 roll from the character's own saved dice (events on the road use the game's own saved dice, `Game.dice`, so a journey replays the same from a save) against the chance their skill gives them (the skill less rust, the governing traits, and modifiers for tools, load and the body's state, against a difficulty): a fine success, success, narrow failure, failure or fumble. Every check teaches a little, more for harder tasks, at a pace set by Intelligence, less and less for the same skill within a day; skills unused for weeks grow rusty, and practice shakes rust off quickly. In play: Swimming in deep water, Athletics under a load and at fords, Climbing on steep ground, Survival sleeping rough and searching for water (Q where there is none), Trading for the day's prices at a market or shop (which now also buys), Persuasion for a better price at an inn, Storytelling and Musicianship (playing for coin) at inns, taverns and markets, Cooking at a hearth or fire (C in the inventory), and mending worn things with the skill and kit each needs (M; boots wear with walking). Teachers at places in town (Seek someone to teach you) and books that teach (R in the inventory) speed learning up to a limit. The log tells outcomes in words; levels, caps and rust are on the character sheet. `npx tsx apps/game/scripts/skills-test.ts` prints the odds and learning curves and checks the rules.

**Camping** (`game/camp.ts`, `game/camping/`, `screens/camp.ts`). Shift+C, on foot or on the travel map, looks about for a camp site and describes the best few (shelter, wood, water, how hidden); the camp is laid out on the local map (fire, woodpile, bedroll, tent or shelter, snares) and saved, and can be gone back to. At the camp: gather firewood, light and feed the fire (it warms those beside it, and burns down unless tended), pitch a tent or build a windbreak or lean-to, forage for what the season gives, set and walk snares, and from evening settle the night (cook, mend, keep watch, keep the fire in, sleep until morning), with placeholder night events (animals at the food, rain, a stranger, wolves) that a watch, a fire, a shelter and a hidden site turn aside. Strike camp to pack up. Raw roots, mushrooms and rabbit are better cooked (C in the inventory beside a fire). See docs/design/navigation.md, Camping.

**Weather, day and night, seasons** (`packages/core/src/weather/weather.ts`, `game/weather.ts`, `game/rain.ts`). Weather is worked out on demand from the seed, the place and the hour: fronts and storms born where and when the climate is wet drift along the prevailing wind, bringing cloud, rain or snow, wind and changes of temperature; snow lies and melts and mud comes and goes from the last fortnight's weather. The sun rises and sets by latitude and season (polar days and nights), the moon has phases, and the light sets how far the wanderer sees; fires, hearths and a carried torch light the dark. The panel pictures the sky (the sun or moon on its way between rising and setting, cloud, rain or snow, fog) with the clock, the wind as an arrow and the temperature, and tells it in words on hover; the log notes changes; Shift+W reads the sky for what is coming (Survival). Rain and snow wet the wanderer by what their clothes keep off (`rain`, `wind`, `sun`, `wool` in the item data), wetness and wind chill take warmth, and fires and shelter dry and warm. The local map is tinted by the hour and firelight, snow lies on open ground, trees and grass turn with the seasons, and rain and snow fall over it; storms stop travel and heavy rain puts out camp fires. `npx tsx apps/game/scripts/weather-test.ts` prints a year of weather for six climates and checks it.

**Item data and mods** (`apps/game/src/data/items/`, `actors/items/defs.ts`, `app/mods.ts`). The items are data, not code: one JSON file per type (`containers`, `clothing`, `armour`, `jewellery`, `weapons`, `tools`, `provisions`, `goods`), described by `item.schema.json` beside them (an editor that knows JSON Schema completes and checks the fields), with `gear.json` for what each occupation's gear becomes at character creation. A field left out takes its default (`durable` true, `hands` 1, no warmth or armour). Food and drink carry a `food` field: kcal and litres of water per portion, and the words for eating it. Books may carry `teaches` (a skill and how far), and things that wear `mend` (the skill, and a kit to carry or things on the map to work beside). `defs.ts` holds the types, checks every item as it is registered and keeps the registry; a fault in the game's own files stops the game at once with the item and the field named. **Mods** are more files of the same form, read at start: in the desktop app every `.json` file in the `mods` folder of the data folder (in name order); in a browser the files listed in `mods/index.json` beside the page. An item with a new id is added; one with the id of an existing item replaces it (a mod can retune bread). A faulty item or file is left out, and the title screen lists what was loaded and what was wrong. For example, `mods/sweets.json`:

```json
{
  "items": [
    { "id": "honey_cake", "name": "honey cake", "kind": "food", "weight": 0.2, "bulk": 0.3, "size": "small", "value": 3,
      "uses": 2, "useWord": "pieces", "food": { "kcal": 250, "verb": "eat some honey cake" }, "durable": false, "sold": ["market"] }
  ]
}
```

### The desktop app

`apps/desktop` wraps the game in Electron (version 45), so it can be played as an ordinary program and, later, keep its saves on disk.

- **Running it.** `npm run dev:desktop` starts the game's dev server and opens it in the desktop window (edits reload as in a browser; View › Toggle Developer Tools). `npm run pack:desktop` makes a build you can run in `apps/desktop/release/` (on a Mac, `World Forge Wanderer.app` in `release/mac*`); `npm run dist:desktop` makes the installers for the computer it runs on (a .dmg and .zip on macOS, an installer and .zip on Windows, an AppImage and .tar.gz on Linux). `.github/workflows/desktop.yml` builds all three on GitHub, by hand from the Actions tab or on a tag such as `desktop-v0.1.0`. The builds are not signed yet: macOS asks you to confirm the first opening (right-click › Open).
- **How it is put together.** The built game is copied into `apps/desktop/renderer/` and served over a private `app://game/` scheme rather than `file://`, where the game's module workers would not load. The page runs sandboxed, without Node, under a content security policy; it can only navigate within the game (other links open in the browser).
- **What the page can do on the computer**, through `window.worldforge` (`preload.cts`, typed for the game in `apps/game/src/desktop.ts`): open a world file with the system's file dialog (also File › Open World File…, Ctrl/Cmd+O), and read, write, list and remove text files in the game's own **data folder** (`World Forge Wanderer/data` in the system's application data folder; File › Show Data Folder), each written whole or not at all. Names are checked so nothing outside that folder can be reached. The game keeps its last world settings and starting town there, and the saved games of the next phase will live there too.
- The window remembers its size, position and full screen (F11, or Ctrl+Cmd+F on a Mac), and a second launch brings the open window forward.

## Climate tuning against Earth

`packages/core/tuning/climate/` scores the climate model on real Earth. It runs the generator's climate pipeline on WorldClim 2.1 elevation (the `heightmap` option of `generateWorld` skips tectonics and erosion) and compares the result with observed WorldClim monthly climatology (1970–2000).

```sh
npm run earth:fetch                      # once: downloads ~46 MB to packages/core/tuning/data/ (git-ignored)
npm run earth:eval                       # score current parameters against packages/core/tuning/climate/baseline.json
npm run earth:eval -- --update-baseline  # accept a new score
npm run earth:eval -- --res=512          # faster, coarser
```

- **Reference map:** the observed monthly data is reduced to the same inputs the simulation produces (mean, warmest and coldest month temperature, summer/winter precipitation) and classified with the same Köppen code. Differences therefore measure the simulation, not the classifier.
- **Reported metrics** (area-weighted over land):
  - exact Köppen class accuracy
  - main-group (A–E) accuracy and Cohen's kappa
  - annual, warmest-month and coldest-month temperature RMSE
  - precipitation log error and bias
  - summer-rain-share error
  - group shares and a confusion matrix
- **Objective:** these combine into one `OBJECTIVE` (0–1, higher is better). The command exits non-zero if it regresses against the baseline.
- **Maps:** written to `out/earth/koppen-{observed,simulated,agreement}.png`. In the agreement map, green is the same class, yellow the same group, and red a different group.

After any change to climate code or `CLIMATE`/`KOPPEN` constants, run `npm run earth:eval` and make sure the objective did not regress. Data: Fick & Hijmans (2017), WorldClim 2.1, CC BY 4.0.
